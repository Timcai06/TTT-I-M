# Darkroom asset library

Built for Blender **5.2.x**, Cycles, metres, Z up. This is a prop library for the supplied darkroom keyframes. It contains no film, camera animation, liquid animation, print-development shader, people, or photographs mapped to paper.

## Files

- `darkroom_assets.blend` — self-contained asset library and a separate neutral studio preview scene.
- `build_assets.py` — deterministic, self-contained Python builder; no downloaded geometry, fonts, textures, Python packages, or add-ons required. NumPy is the version bundled with Blender.
- `previews/DR_*.png` — one **1600 × 1000** Cycles diptych per asset family. Left: 3/4 overview. Right: a 70–100 mm close-up at 22–39 cm. Depth of field is disabled for inspection.
- `preview_gallery.html` — local, clickable preview gallery.
- `previews/DR_ContactSheet.png` — overview of all eleven families, in the table order below.
- `asset_manifest.json` — measured dimensions, topology/UV checks, fill volume, render settings and pivots.
- `verification.json` — independent reopen/append, controller, evaluated mesh and preview checks from Blender 5.2.1.
- `verify_assets.py` — repeat those independent checks without modifying the blend; the report records hashes of the checked blend and builder.
- `references/` — the three supplied keyframe targets. These are also packed into the blend as `DR_Reference_*` images; they are not applied to any prop.

## Rebuild

Run from this folder:

```sh
blender -b -P build_assets.py
```

On this Mac, the executable is `/Applications/Blender.app/Contents/MacOS/Blender`. To avoid loading personal startup add-ons, you may add `--factory-startup` before `-P`.

The script writes beside itself, regardless of the current working directory. The default command builds, validates, saves and renders every asset family. It uses Metal on supported Macs, another supported Cycles GPU backend when available, or CPU otherwise. The references are optional inputs to rebuilding; all prop materials and label textures are generated by the script itself.

```sh
# Rebuild the blend without rendering previews.
blender -b -P build_assets.py -- --no-previews

# Render an existing blend again without rebuilding its assets.
blender -b -P build_assets.py -- --preview-only all --samples 128

# Render specific families from the existing blend.
blender -b -P build_assets.py -- --preview-only DR_Tray,DR_Sink --samples 128

# Force CPU if the local graphics driver is unavailable.
blender -b -P build_assets.py -- --cpu

# Independently reopen and verify the delivered blend and previews.
blender -b --factory-startup --python-exit-code 1 -P verify_assets.py
```

## Append and assemble

Append the desired `DR_*` **Collection** from `darkroom_assets.blend`, or use the marked collections in Blender's Asset Browser. Append the collection rather than individual geometry pieces so parents, spring/line controls, Boolean operands and packed materials stay together.

`DR_Assets` contains only props and helpers: it has no camera, light or world. To avoid overlapping props on opening, its initial view layer shows only `DR_Tray`. Enable another collection in the Outliner, or append collections to the artist's assembly scene.

`DR_Preview` is the separate studio scene. Its `DR_Preview_AssetInstance` references the asset being inspected. All studio cameras, lights, world and floor are confined to that scene/rig collection.

## Liquid hand-off

`DR_Tray_LiquidBounds` is hidden in both render and viewport. Unhide it when required. Its top is at **Z=0.0385 m**, giving **35 mm of fill above the 3.5 mm interior floor**.

The volume uses the same inner-wall ring profile as the tray. A live Boolean subtracts the floor ribs, so it is a closed interior volume rather than a rectangular proxy. Duplicate it for the artist's liquid work; retain the original helper as the fit reference. The measured evaluated volume is in `asset_manifest.json`.

The helper is not a water surface shader or a fluid simulation. Actual surface deformation and animation belong to the scene artist.

## Paper UV and deformation

Both sheets use the full **0–1 UV square**, with U along the 8-inch axis and V along the 10-inch axis. The 10×8 physical orientation is a clockwise rotation of that same portrait UV convention. The border is not reserved in UV space; any photographic border must be in the mapped print image or shader.

`DR_Pin_TopEdge` contains the physical top row for hanging/cloth pinning. The `DR_Hanging_Curl` shape key supplies an optional gentle bow/curl. It is **0 in the saved asset**, and temporarily 0.65 only in the paper inspection preview. The separate `DR_Paper_Tooth_Bump` material node provides micrometre-scale surface tooth without altering the paper silhouette.

## Surface and naming notes

All prop surface shaders use a Principled BSDF. Grain, scratches and wear are procedural. Bottle-label marks and cylinder ticks are generated raster textures packed into the blend. Labels carry only illegible pencil-like strokes; cylinder markings have no numbers. **Only the timer has readable numerals**, per the user's explicit clarification. There are no logos.

Bevel, Solidify, Subdivision, Hook and useful Boolean modifiers remain live. The tiny slotted-screw prototype's machined slot is baked into its shared mesh; each screw retains its edge bevel. Hidden drain cutter meshes are helpers, not visible props.

The assets are supplied at their physical sizes. Wall-mounted/hanging assets retain their requested pivots: safelight wall mount, line left endpoint, and paper top edges. Position these in the assembly scene rather than resetting their geometry to a floor origin.

## Validation boundary

The build validates names, material shader types, packed resources, paper grid/UV/thickness, world/camera/light separation and the evaluated liquid volume's closed topology. A separate reopen check also inspected 290 evaluated solid meshes, exercised the clothespin and line controls, verified the pinned paper edge, and appended all eleven collections into an empty file while preserving controllers and packed materials. The intentionally open graduation decal and hidden helper cutters are excluded from the closed-solid check. The detailed results are in `verification.json`.

The rendered PNGs are actual Cycles renders of these assets and were visually inspected. The small clothespin and line close-ups use a portrait sensor crop to show the spring and fibres while retaining the specified lens and working distance. Technical checks establish file and control integrity; final visual acceptance remains with the artist and tim. Scene lighting, animation, development shader and the finished film's match cut are outside this delivery.
