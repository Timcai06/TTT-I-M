The current folder has **reverse chapter imports** that could introduce chapter ↔ feature cycles through a shared barrel after a wholesale move. At baseline `4155975`, `PersonalArchiveBridge.tsx:8,71` imports/renders `components/AboutDossier`; `ArchiveAbout.tsx:2` imports `components/About`; `ArchiveHandoffPage.tsx:3-10,18-30` imports Projects, Contact, `LifeIntro`, `StackContinuityFrame`, and `frame/ArchiveTextPanel`. `ArchiveChapters.tsx:7-10` is already a safer pattern: it accepts `children` supplied by a chapter and only owns the spatial wrapper. Completed 2A (`8de990b`) moved the latter chapter-owned files to `chapters/about/About.tsx`, `chapters/life/LifeGallery.tsx`, `chapters/skills/Skills.tsx`, and `chapters/frame/ArchiveTextPanel.tsx`; the adapter imports now target these paths.

Proposed boundary: keep `ArchiveAbout` as the About chapter composition, and keep the multi-chapter handoff DOM composition at the chapter/app layer rather than inside the low-level room feature. Make `PersonalArchiveBridge` receive About DOM as `children` (or an explicit slot) from that composition. Let `ArchiveChapterBridge` receive handoff content as a React node/slot from the caller, while `ArchiveChapters` keeps its existing `children` API. The feature owns canvas, projection, scroll/seek adapters, fallback container and stage lifecycle; chapters own About/Frame/Life/Skills/Projects/Contact text and artwork. This requires moving the composition imports and checking DOM order/measurements, not substituting empty placeholders.

Keep domain ownership explicit: `core/narrative` remains a shared story contract (`archiveRuntime.ts:38-39`), `lib/resources` remains preloading, `lib/archiveRoute` remains global navigation, and chapter content/DOM remains in chapters. Publish narrow feature entry points for the stage and chapter bridges, plus a separate lightweight type/routing API. Do not use one feature barrel that statically exports `archiveRuntime`/Three/WebGL into the app boot path. The existing lazy `App.tsx:24`, optional preload `lib/resources/manifest.ts:203-208`, global route `lib/archiveRoute.ts:4-7`, and sound listener `lib/sound/roomListener.ts:16` would need coordinated import changes in the **next** migration, not this 2A round. Preserve mobile/reduced-motion fallbacks (`ArchiveChapters.tsx:2-10`) and the single fixed canvas across seek/navigation (`ArchiveStage.tsx:18-20`).

Keep source assets and export contracts fixed during a path-only move: `archiveRuntime.ts:13` resolves the shipping GLB URL, `archiveDirector.ts:3` reads `assets/personal-archive/scene-contract.json`, `ArchiveRoom.tsx:5` historically reads `cameras.json`, and model object names are enforced through `sceneBindings.ts`/the exporter. Rewrite relative imports without changing the GLB bytes, scene JSON, node names, Blender source, or generated asset locations.

Do **not** fold the disconnected R3F `ArchiveRoom`, `ArchiveChapterRoom`, `ArchiveLighting`, `ArchiveSignal`, `chapterProjection`, or old shadow writer into the proposed feature. Their separate retirement is assessed in `legacy-modules.md`; keeping them out of the move prevents two apparently authoritative renderer paths.

Implementation gate for a later card: move one dependency group at a time with import rewrites, use the existing build/unit/e2e checks for preload, room entry, sample seek, chapter return, context recovery and mobile fallback, then inspect a rendered room. A passing import graph cannot certify lighting or timing. No implementation is authorized by this assessment alone.
