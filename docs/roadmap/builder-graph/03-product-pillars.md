# 03 · 产品支柱

## 1. Project Graph

Project Graph 是核心视觉和数据结构。它把 repo、项目、技术栈、主题、时间、贡献类型连接起来。

它回答：

- 我做过哪些项目？
- 哪些项目属于同一能力线？
- 哪些 repo 是练习，哪些是产品，哪些是实验？
- 我的项目之间有什么演化关系？

图谱不是装饰，它是用户理解自己的入口。

## 2. Growth Timeline

Growth Timeline 把 GitHub 活动从按日期排序，升级为成长阶段：学习、试验、第一次完整项目、第一次部署、第一次重构、第一次协作、第一次 AI 系统、第一次后端服务。

它回答：

- 我什么时候开始从练习走向产品？
- 哪些提交代表能力跃迁？
- 哪些项目虽然小，但对成长很关键？

## 3. Skill Radar

Skill Radar 从 evidence 中推断能力信号，而不是让用户手填百分比。

能力可以来自：

- 语言和框架使用。
- commit 类型。
- PR / issue 协作。
- CI / Docker / deployment 配置。
- README 和文档质量。
- 数据库、后端、AI、算法、可视化、测试等结构性证据。

Skill Radar 应该表达趋势和证据，不应该制造虚假的精确分数。

## 4. Contribution Digest

Contribution Digest 把 commit / PR / issue 翻译成人类可读的进展记录。

它不是简单罗列提交，而是帮助用户理解：

- 这一周我完成了什么？
- 我修复了什么问题？
- 我在哪些能力上变熟了？
- 哪些改动值得写进项目故事？

## 5. Portfolio Composer

Portfolio Composer 把 Project Graph 转化为公开作品叙事。它帮助用户选择最值得展示的项目、组织项目顺序、生成初稿、补齐缺失信息。

它不是一键生成假简历，而是把真实证据整理成更清楚的表达。

## 6. AI Mentor

AI Mentor 是用户的复盘伙伴。它的语气应该像一个认真读过你代码的导师：具体、鼓励、诚实、能指出下一步。

它可以建议：

- 哪个 repo 最值得完善 README。
- 哪个项目最适合部署成 live demo。
- 哪些技能证据不足。
- 哪些项目可以合并成一个更强的 case study。

## 7. Public Growth Profile

Public Growth Profile 是用户可分享的成长主页。它展示项目图谱、精选项目、成长时间线、技能证据和 AI 辅助整理后的介绍。

它应该既适合求职/申请，也适合长期记录自己。

## 8. Private Reflection Mode

不是所有成长都要公开。Private Reflection Mode 允许用户只为自己生成复盘、周报、草稿和下一步建议。

这部分的产品语气要温柔：半成品也是成长证据。
