## 1. 产品决定与旧方案的关系

房间是浏览的持续场所，章节是打开物品后展开的内容。一次会话共用同一个房间、相机和物件状态。深度阅读可以扩大内容，但入口、边缘线索、退出位置始终说明内容属于哪件物品。

本稿替代旧稿中以下决定；既有修复证据仍保留其历史意义。

| 原有决定 | v2 决定 |
| --- | --- |
| 全屏 Hero → 第一次进入空间 | 开屏结束即为房间；现有 Index 在电脑屏幕中 |
| 在各章节之间重复显现房间 | 房间构图连续变化，各章节从物品展开、向物品收回 |
| 电脑默认 PulseGraph | 网站初始屏幕使用可交互 Index；现有模型资产的默认贴图无需在本轮重写 |
| 每段从黑色章节底重新显现 | 黑色用于开屏及原内容配色；正常旅程中不重复黑场/灰场进入房间 |
| 章节第一帧对齐即完成接续 | 入场、阅读、收回、移往下一件物品四段都必须连续 |
| 导航直达脱离空间的原网页 | 保留直达效率，在目标物品对应的阅读状态落地并能返回原处 |

屏幕的 Index 不是整站嵌套浏览器，不增加桌面操作系统、应用启动器或控制房间的菜单。现有 Index 本页实际存在的粒子、文字和签名等交互继续有效。全站章节导航仍属于房间外层的导航。

## 2. 现状证据与设计缺口

2026-09-08 只读检查：main 的提交基线为 55c4ad3，工作区另有 DEV 未提交的转场实现。本稿不回退这些改动。

- `App.tsx` 按 chapter registry 依次渲染完整章节；Hero 自身具有入场、粒子肖像、文字交互和依赖页面滚动位置的生命周期。
- `ArchiveChapterBridge.tsx`、`PersonalArchiveBridge.tsx` 分段持有空间入口；`archiveRuntime.ts` 已共享 renderer，但仍会将 canvas attach 到不同 host，释放时移除。共享 GPU 不等于连续的空间体验。
- `archiveDirector.ts` 按 shot 重建姿态。例如 Life 物件动作在后续不相关 shot 中回到 0；需要改成整段旅程明确的姿态契约。
- `scene-contract.json` 已有 home/about/life/frame/stack/work/contact 视角和五组阅读面四角，足以先验证新空间结构；没有 Index 专用行为契约，也没有独立 Contact 阅读面。
- 最新 DEV 通过真实章节组件改善交接内容一致性。它解决了“展示什么”，仍需解决“内容始终在哪里”。

这些是结构判断，不代表当前界面的视觉验收。

## 3. 第一眼：坐到我的书桌前

开屏完成后，第一帧是已绘制的房间。相机位于书桌前方略偏左，面对显示器；显示器、左前方笔记本、右侧台灯同时可见，窗和书架提供纵深。采用有人坐在桌前的视线高度，避免开场俯看整个模型盒子。

首屏主体为电脑，显示器外轮廓以视口宽度约 42–50% 为构图起点；书桌和灯光使其明确处于房间中。实际位置由已有 home/stack 视角之间的安全构图确定，数值是设计起点，不是假定已验证的相机坐标。

屏幕内呈现原 Index 的身份排版、肖像、签名和背景效果，保持原比例。首屏不要同时在屏幕外再复制一份大号姓名或第二个 Index。原全局导航在外层仅保留一份，保留原字体语言。

电脑从出现时就可以响应指针。用户点击屏幕空白处或由键盘选择“靠近屏幕”，相机轻微推进，屏幕达到约 65–72% 视口宽度并归正到舒适角度；边框、底座和台灯仍提供空间位置。无需先点击才能激活本页原有交互。

默认无自动环绕、呼吸式相机晃动或强制等待。Index 的本页入场可以播放，但首帧已有可辨认的身份信息，滚动始终可立即打断并开始房间路线。

## 4. 全站分镜

顺序保留 Index → About → Life → Frame → Stack → Work → Contact。每次“继续”都从刚读完的物品出发，不返回房间首页重新起步。

| 阶段 | 相机与物品 | 原站内容如何存在 | 离开后的空间状态 |
| --- | --- | --- | --- |
| Index · 屏幕 | 桌前中近景，电脑为中心，笔记本在左下 | 只运行 Index 本页，屏幕内指针互动真实有效 | 电脑保留 Index；相机向左下转向书 |
| About · 笔记本 | 先看见封面/书脊，封面开启，再向完整档案页推进 | 原 About 的标题、头像、排版、内容全部进入书页；展开后保留暗色原风格 | 退出先显露纸边与桌面，书保持打开 |
| Life · 书架信封 | 从仍打开的书抬起，沿书架移向信封，照片抽出 | 同一张真实照片进入原 Life 图组；保留 DriftWall 与原文案 | 阅读收束为可追踪的照片组，信封和抽出的照片留在架上 |
| Frame · 照片墙 | 从书架转向右侧照片墙，先建立墙角/台灯的方位，再靠近照片 | 原索引及 Building/Cuisine/Scenery 横向叙事成为摄影档案展开面 | 相机退回最后浏览照片，挂杆仍在原位 |
| Stack · 再看电脑 | Frame 最后一张 Final Horizon 在墙上清楚可见；退开让墙上照片与电脑短暂同框，屏幕显示同图，然后靠近 | 同图接续现有 Stack 内容与红线。文字等图片稳定后出现，不插替代标题卡 | 离开时从屏幕退回桌面；屏幕显示 Stack 停留状态 |
| Work · 档案抽屉 | 从电脑沿底座向下、向右看抽屉；抽屉拉开、档案抬起 | 原 Work 开场、Glass、项目卡片与详情完整展开；真实项目封面对应实际选项 | 退出详情回原卡片，退出 Work 才收回档案；抽屉保持微开 |
| Contact · 桌边 | 从抽屉抬起并略微后退，看到打开的书、电脑和台灯 | 原 Contact 在桌边安静展开；邮箱和社交链接保持真实可点击 | 房间停稳，不熄灯。返回 Index 回到电脑并恢复 Index |

Frame → Stack 的同图连接表达“同一张照片在房间的两种载体上被观看”，不把实体挂画飞过房间贴到电脑上。允许用现有图像/粒子语言强调一次交接，照片主体要始终可追踪，且不能跳过看见电脑的阶段。

Contact 首版采用与桌面位置对应的阅读界面，不因为缺少独立 Contact 模型就把联系方式映射到 Work 档案上。需要实体卡片时再提出局部建模任务。

## 5. 阅读时怎样仍然感到在房间里

默认阅读构图让原章节占视口约 90–94%，外围留出约 24–48 CSS px 的空间边缘作为起点；具体跟随窗口与内容安全区调整，正文行宽、字号、图片裁切优先保持原有质量。空间线索不能靠在黑页后继续运行却完全不可见的房间来代替。

每章至少保留一个有意义的边缘：About 的书页/书脊，Life 的纸边与书架局部，Frame 的挂杆/相纸，Stack 的屏幕边框，Work 的档案页边和抽屉，Contact 的桌沿与暖光。线索不能变成重复套用的厚边框模板。

阅读面归正后相机固定，鼠标不再推动整个房间。文字在正面、清晰、可选择的界面上阅读；原站动画由正文滚动驱动。背景光保持窗侧冷光和台灯暖光的稳定方向，不给原图片强行加色、不给正文字形叠景深。

原来依赖全视口的特殊段落允许短暂铺满屏幕：Frame 横向大图、Work 项目影片等保留原构图。进入和退出这些段落必须接续当前物品边界，外层始终保留简洁的“返回书桌 / 返回照片墙”等位置入口。不能为了空间边缘把所有章节简单缩小到原来的 92%。

关键镜头：About 中最后一段仍是实际读到的内容；开始退出时，这一阅读面收回书页，先露出纸张厚度、书脊，再露桌面。不得突然换回 About 第一屏才能做动画。模型无需为每个正文段落制作真实翻页，界面滚动表达内容，封面与少量页边表达物理载体。

## 6. 输入与导航：一个时刻只有一个滚动对象

| 操作位置 | 行为 |
| --- | --- |
| 初始房间/电脑 Index | 指针作用于屏幕本页；滚轮控制房间旅程，不在电脑里再套一个整站滚动条 |
| 开合/靠近物品 | 滚轮控制当前相机与物品进度；停止滚动即停止推进，反向沿原姿态退回 |
| 正文阅读 | 滚轮只控制当前原章节叙事，相机保持不动；Frame 横向等行为继续由该章节负责 |
| 正文末尾 | 自然滚动进入收回过程；先看见当前内容的载体，再开始转向下一件物品 |
| 点击物品/外层章节导航 | 从当前姿态启动一条有空间依据的直接路线，约 0.6–1.2 秒作为初值；不依次播放中间全部章节；新输入可打断 |
| 快速滚动 | 可以跨越多段，但最终姿态和当前章节必须由目的状态直接建立；不排队补播漏过的动画 |
| 正文“返回物品” | 缓存当前阅读位置，收回至当前物品近景；再次打开恢复阅读位置 |
| Escape | 优先关闭项目详情；其次退出屏幕近看/章节阅读回当前物品；在房间中无强制导航 |
| 直接打开 #about/#frame/#skills/#projects/#contact | 准备好后进入对应阅读状态并建立背后的物件姿态，保持原地址语义；无需观看开场路线 |
| 返回/前进 | 恢复章节、详情和已有阅读位置，不额外积累自动滚动的历史记录 |

没有第一人称行走按键、自由绕屋轨道或拖拽旋转整个房间的必修操作。自然滚动就能浏览全部内容，点击物品提供另一条入口。热点只在可见且未遮挡时出现，悬停或键盘聚焦显示简短名称；不在房间铺满常驻发光标记。

电脑的屏幕交互与路线冲突时，以明确规则处理：指针 hover/click 交给 Index；wheel 交给旅程；指针离开屏幕即清除屏幕 hover。聚焦交互元素时关闭房间微视差，避免目标移动。外层浏览器链接保持正常语义，不凭空把 Index 文案改成控制房间的命令。

## 7. 空间记忆与可逆滚动

区分两种状态：物理姿态由路线位置决定；阅读位置和访问记录按会话缓存。禁止把“看过”直接用作动画时间，造成倒滚姿态不可恢复。

顺序旅程中：书打开后在后续站点保持打开；Life 之后信封保持打开、照片已抽出；Work 之后抽屉保持微开。返回 Index 的快捷导航保留已有会话状态，屏幕恢复 Index。本次会话刷新后可从地址所需的合理默认姿态建立，无需首版做跨天记忆。

离开正文要保留当前内容位置；跳章后再次打开恢复之前的阅读位置。直接深链没有历史时使用目标章起点。点击路线被滚轮打断时，从当前可见姿态继续或归入最近的合法路线段，不瞬移到预设 from 视角。

模型姿态表、正文进度、导航目的地由一个导演状态协调，切换到某个 shot 不能把其他物件顺手重置。

## 8. 给开发的结构约束

以下是建议责任边界，不要求照搬命名，更不要求在一个巨型组件里重写整站。

| 职责 | 落地要求 |
| --- | --- |
| 持续房间舞台 | 复用当前 shared runtime 与安全材质处理，房间 canvas 挂在稳定 host；切章不搬运、不卸载这张 canvas |
| 空间导演 | 合并空间路径、阅读阶段、物件姿态与导航意图；同时明确原章节拥有自己的内部进度 |
| Index 屏幕面 | 抽离现有 Hero 内容/交互与全局 scrollY、intro/arrival 依赖；提供局部视口、可见性、指针坐标和进度，避免原代码 scrollY > 6 就关闭屏幕交互 |
| 正文章节容器 | 一份真实内容驱动投射和阅读，原组件保留内容与风格；投射副本若不可避免，只能有一个互动/可访问实例 |
| 内容交接 | 从实际源面测量投影四角，与真实目标排版共用图像裁切与文字布局；禁止用几个随意 vw 关键帧假装物品跟踪 |
| 路线与地址 | 保留既有 hash、项目详情和导航职责；空间状态与阅读坐标一起恢复 |
| 资源与降级 | 在开屏内完成核心资源、图片解码、字体、着色器预热和关键视角有效绘制；失败保留可操作内容与直接阅读入口 |

电脑屏幕首版优先用标准浏览器能力制作真实可交互的透视界面，绑定已有 StackReading 四角和显示器内框。使用屏幕局部坐标还原原有指针效果；字体字号按局部虚拟视口布局。投影面必须有边界裁切、遮挡判断和背向隐藏，不能隔着书或桌子仍然可点击。

现有 Hero 的粒子渲染与 HTML 内容需要保持同步。具体采用 DOM 合成、可交互表面加局部粒子层，还是共享渲染目标，由开发先提交一个屏幕试验的兼容性与命中证据。不要把“能生成贴图”当成“真实交互已实现”，也不要把需要 Chrome 实验 flag 的方案作为默认体验。首版不得把 iframe 中再运行整个 App 作为屏幕实现。

所有字号、定位和投影以当前章节容器尺寸计算。现有使用 window.innerWidth/innerHeight、100vw、pin、横向轨道的模块必须单独检查；给外层加一个 transform 缩小整页会破坏排版、滚动测量和点击坐标，不能作为迁移方案。

原有异常像素/NaN 防护和上下文恢复保留。持续存在不代表持续满帧：正文相机静止且房间无变化时可停止重复绘制；Index 只在屏幕可见并处于相关状态时更新。GPU 恢复先保住当前阅读内容和最后有效画面，不能暴露灰色清屏帧。

## 9. 建模边界

本设计先使用现有唯一 .blend、GLB、五组阅读面和物品动作。首轮验证对象是“房间—屏幕—书本—正文—返回桌面”的关系，暂不新增模型或改装修。

开发需要检查而非假定：屏幕有效内框与 StackReading 是否完全对应；书页近景是否保留可见厚度；Life 抽出照片是否可作为真实定位面；Work 页边与抽屉是否足以承担退回镜头；camera 路径是否碰到椅背、灯臂、书架。

只有上述试验确认存在实际缺口，才列出局部建模任务，附物件名、观察视角、阻塞的交互以及最小修改范围，再交 tim 决定。Contact 暂不新增卡片；不另建 .blend。

| S2 空间阅读模式 | Life、Frame 的空间展开、完整原叙事与收回；阅读位置缓存、反向与直达 | 文字图像映射准确，Frame 原有横向体验保持，退出看得见内容回到哪件物品 |

S1 用于尽早识别空间主体体验的缺口。S0–S4 按最新授权连续实施；已有文案替换、屏幕同图、加载修复等可复用，不代表已经满足 v2。

## 11. 验收标准

### 产品与视觉，由 tim 判定

- 开屏之后第一眼看到房间和电脑里的 Index，首屏不存在房间外的第二份 Hero。
- 离开屏幕到书本的镜头能保持桌面方位；About 是书里展开的完整内容，收回时仍然是刚刚阅读的那一页。
- 任意章节阅读中能辨认其物理载体；回到空间不会经历黑/灰重开、标题卡或陌生视角。
- 原站的衬线/等宽文字、暗色配色、图片、Frame 横向叙事、Stack 红线、Work Glass 等表达保留。
- 空间感来自具体物品、相机方位、动作和内容关系，不靠长时间飞镜头和强制等待。

### 技术证据，由开发提交、PM 审查

- 屏幕中心、边缘、四角的指针映射、点击和键盘焦点有效；变更窗口后坐标不漂移，遮挡/背面没有幽灵命中。普通 Chrome 和 Safari 均有记录，不依赖实验开关。
- 交接期间源与目标的文字/图像锚点误差目标 ≤1 CSS px、对应图像裁切误差 ≤0.5%；记录整个可见交接区间，不只记录终点。正文末尾退出也要测量。
- 桌面 1280×720、1440×900、1920×1080 及可用的 DPR 1/2；前进、倒滚、快跳、停住 500ms、交接中 resize、浏览器前进/返回与深链都有检查记录。
- 所有空间路径复用之前对 raw room / 后处理输出的异常像素检测；不以状态 ready、FPS 或几何测试代替像素覆盖检查。
- 开屏退出前记录资源就绪、字体/图片稳定、GPU 预热与有效第一帧；冷/热缓存、网络限制、失败重试与 GPU 恢复分别记录。不能用“进度 100%”推断画面已准备好。
- 检查一套页面滚动所有权、一次有效焦点、详情关闭恢复、当前页退出复原；空间静止时没有相机漂移。
- 在实际 M5 Pro 上记录性能分布、最长卡顿、活跃 contexts 与资源占用，先比较基线再定性能预算；不要凭硬件型号承诺所有高质量效果同时满帧。
- 构建、类型、现有测试及第三方 hash guard 独立报告；遗留失败不能伪装为本轮全绿。
