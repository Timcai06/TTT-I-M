# 整站交互与转场交接规格

> 当前实现更新：主线交接、照片查看及详情 URL 已接入，见[网页交付](../delivery/web-choreography.md)。本文保留设计 v1；其中逐张照片卡位匹配、长文首图副本回收等细节以交付记录的明确取舍为准。

版本：设计 v1 · 2026-09-07。配套 [全站叙事](full-site-choreography.md) 与 [建模任务](../assets/chapter-modeling-plan.md)。本文补齐开发所需行为；新增部分尚未实现。

## 1. 转场分镜与默认节奏

进度属于各交接段自身的 0–100%，不是整页进度。下面是开发默认值，视觉节奏由 tim 在成品中调整。滚动型动画始终直接采样进度，不能播放一个必须等待结束的定时动画。

| 交接 | 0–25% · 建立对象 | 25–60% · 空间动作 | 60–85% · 内容接续 | 85–100% · 阅读接管 | 实际滚动默认值 |
| --- | --- | --- | --- | --- | --- |
| Life → Frame | 固定交接照片，漂移收敛 | 露出纸边和夹具，沿墙侧移 | 摄影索引与照片位置对齐 | 墙面退出，Frame 索引归正 | 110svh |
| Frame → Stack | 末张风景保留主体，边缘离散 | 信号汇聚到显示器里的同图 | 显示器靠近，Stack 标题与红线建立 | 边框越出视口，红线接管 | 140svh，替换原交接 |
| Stack → Work | 红线沿桌沿到抽屉标签 | 抽屉拉出，首份档案抬起 | 封面归正，Work 开场接续 | 归还正文滚动，Laser 停止 | 120svh，替换原交接 |
| Work → Contact | 档案页边缘重新出现 | 略微拉开至桌边与暖光 | Iris 揭示文字安全区 | 联系入口稳定，环境停止连续渲染 | 80svh |

Hero/About 已实现的滚动距离与书页动作保持当前基准。About → Life 的照片进入 DriftWall 安排在已有退出段尾部完成，优先重分配末段区间，不再多插一整段房间过场。

## 2. 起止画面的对应关系

每条交接必须明确源内容、目标内容和末帧几何。物件模型负责纸边/夹具/边框，正文组件负责清晰文字；到达末帧时展示副本和真实节点重合，不能出现两个首屏。

| 边界 | 源画面 | 目标画面 | 不可断开的对应 |
| --- | --- | --- | --- |
| 书页 → About | `AboutDossier` 展示副本 | `#about` 内同一组件 | 标题、头像、行宽、颜色、四角 |
| 信封照片 → Life | `LifeMemoryPhoto` | Life 首张展示照片 | 同一资源、原始比例与裁切中心 |
| Life → Frame | 显式配置的交接照片 | Frame 对应主题索引图 | 图像内容、纸张边缘、横向运动方向 |
| Frame → 屏幕 | 风景主题实际选定的尾图 | 显示器内图像 | 同一图像与粒子采样源 |
| 屏幕 → Stack | Stack 开头展示副本 | `#skills` 标题与首行 | 标题基线、红线起点、可读对比度 |
| 档案 → Work | 首份档案上的开场内容 | `ProjectsIntro` 对应内容 | 项目/标题身份、图像比例、文字位置 |
| 项目卡 → 详情 | 点击时的活动图片 | `heroShot` 对应详情首图 | 图片标识、当前裁切、标题与封面边界 |
| 档案页 → Contact | 桌边留白中的联系开头 | `FooterContact` | 标题位置、邮箱可点击区域 |

内容绑定集中在配置中，以内容 ID 和图片资源共同核对。实施时从已有内容仓储选择图片，保存明确 ID；文档不虚构用户尚未提供的作品或图片。缺少对应内容时不随机取轮播当时的图片，直接保留原章节。

## 3. 章节导航、目录与当前状态

导航继续使用已有 Home、About、Frame、Stack、Work、Contact；Life 仍是主线中的生活间奏，不新增一个与旧导航竞争的顶栏。所有链接对应真实阅读锚点。

滚动交接前半段显示源章节，越过 60% 后可更新小号章节提示；章节导航的 active 状态仍由统一章节状态系统决定，不由每个模型组件单独修改。

点击导航时直接定位目标正文。准备好目标章节的最终姿态即可，不让相机飞越中间全部物件；导航期间关闭旧段展示副本和指针提示。倒滚进入相邻空间段时再恢复对应物件的进度状态。

目录沿用现有入口。展开为右侧索引面，宽度取视口的 38%、上限 560px；空间/正文保持当前位置，背景只降低对比度。当前章节带序号与细线；点击条目关闭目录并直达，Escape 或关闭按钮恢复打开目录前的焦点。目录内不再提供另一套自由漫游导航。

桌面短视口首先缩小留白和图片区高度，标题保留原站字号体系并允许原有断行。投影矩形依据实际视口测量；不把 1440×900 当成固定坐标系统。这属于桌面适配，手机端仍不在本轮范围内。

## 4. 项目详情的完整生命周期

### 打开与关闭时序

打开默认 850ms：前 100ms 确认点击和聚焦封面；100–650ms 源图展开并移动到目标首图；650–850ms 正文与工具栏进入稳定阅读状态。源图保持完整中心，粒子只在边缘强调运动。关闭默认 620ms：先收束正文，再将首图副本回收到源卡片。

图片/模块未准备好时不启动几何展开，卡片保持可见并提供“正在打开…”状态。500ms 以内不插入额外加载层；超过 500ms 显示卡片内状态，8 秒仍失败则恢复卡片并给出重试。关闭操作不等待网络完成。

详情打开后背景列表滚动暂停，滚动进入详情自身的正常文档流。与 3D 主线共用页面身份，但模型不占用正文画面。关闭按钮固定在详情工具栏，键盘焦点限定在详情内；Escape 和浏览器后退都可退出。

### URL 与返回：设计已确定，待开发

使用 Landing 自己的查询参数表示详情：`/?project=<project-id>#projects`。不引入 Studio 路由，也不把外部项目地址改写为内部详情。

- 从列表点击：保存列表滚动位置和触发节点，写入一次 history 条目；关闭后回到该条目之前的列表状态。
- 直接访问详情链接：先建立 Work 的稳定阅读状态，再显示项目。缺少源卡片测量时使用简短归位入场，不伪造远距离飞入。
- 关闭直接访问的详情：移除 `project` 参数并留在 Work，不执行可能离开本站的盲目 `history.back()`。
- 浏览器后退/前进：从 URL 恢复列表或详情；不重复 push history，不重新播放全站开场。
- 无效项目 ID：清除无效详情状态，保留 Work 和短提示；不进入黑屏或空弹窗。
- 详情开启期间：章节滚动监听不能覆盖详情 URL。导航选择其他章节时先退出详情，再执行那一次导航意图。

实现统一 URL 更新函数，保留其他已存在的查询参数；不在各组件中手写互相覆盖的 hash 和 search。

### 竞态与长文关闭

一次只允许一个详情转场成为当前动作。点击 A 后快速点击 B，如果尚未进入 A，则取消 A 并进入 B；如果已经阅读 A，则先完成可取消的收束，再进入 B。失效回调不能重新打开已关闭的项目。

长文关闭时记录当前正文位置，使用首图展示副本完成退出；不把真实详情先跳回顶部给用户看。源卡片仍有效时返回其图像矩形；否则恢复 Work 保存的位置，再将焦点放回项目标题或章节标题。

## 5. 照片查看与可选探索

普通滚动承载全部主内容。照片查看器继续采用项目内现有照片展示基础能力；Life 若尚无点击连接，则在后续实现时接入同一查看路径，不能假定已经存在。

点击照片从当前图像位置放大，显示真实标题/拍摄说明；左右切换只在所属照片集合内进行，关闭回到该照片。图片没有说明时不编造地点或拍摄背景。

照片背面、手写注释、杯具和灯具交互列为后续可选探索，本版不实施。正文入口不隐藏在无标签物件中，悬停与键盘聚焦提供一致的可操作反馈。

## 6. 加载、失败与快速输入

| 情况 | 显示内容 | 滚动/输入处理 | 资源处理 |
| --- | --- | --- | --- |
| 下一场景未加载 | 保留当前正文或入口提示 | 继续允许滚动与直达 | 接近视口才预取 |
| Canvas 创建但未提交绘制 | 与等待状态相同 | 不提前隐藏正文 | 首帧超时仍受监控 |
| 用户已经滚过转场 | 直接显示目标正文 | 不强制回拉 | 取消过期加载/动画 |
| GPU 配额暂满 | 保留 DOM/静态展示 | 不中断阅读 | 等待准入或释放离场面 |
| 模型/纹理加载失败 | 原章节与明确阅读入口 | 不留空黑段，不锁滚动 | 中止过期任务，停止重试风暴 |
| 倒滚重新进入 | 按当前进度恢复姿态 | 无需先播完整动画 | 从缓存恢复，仅近场挂载 |
| 窗口大小变化 | 保持可读页面 | 重新测量后接续 | 废弃旧投影矩阵 |
| 页面切到后台 | 保持当前状态 | 恢复后读最新进度 | 暂停渲染与定时动画 |
| 开启减少动态效果 | 保留原章节与导航 | 跳过空间运动 | 不为被跳过的场景创建 context |

以上复用已修复的首帧就绪契约。任何优化都不能把 `onCreated` 重新当作画面已出现的证据。

## 7. 设计完成边界

本版已确定全站主线、四段新增/重编排交接、项目详情、目录、照片查看、URL 行为、资源等待与失败退路，以及各段建模职责。后续可直接按实施顺序开发，不再需要先决定整站采用哪一种体验方向。

具体相机世界坐标、物件角度和源图 ID 在对应资产与章节接入时从实际资源计算并记录；像素级对齐和美术节奏在成品中由 tim 验收。它们是制作和调校工作，不应在设计文档中以未经测量的数字冒充完成。
