# Personal Archive v2 · 美术与运动交付规范

## 1. 参考站观察与本站取舍

2026-09-08 再次直接操作 [Unseen 首页](https://unseen.co/) 和 [Projects](https://unseen.co/projects/)，在 1280×720 浏览器视口观察无声入场、首页、导航进入作品页及其稳定画面。未测参考站 FPS、精确时长、GPU 负载或内部实现。

本次观察：首页以拱门、窗洞和台阶建立纵深，水面提供流动反射，主体球体与粗糙石块有明显材质区分。居中的大标题获得留白。进入 Projects 后，内容网格占据中部，明亮的建筑环境仍在外围可见，顶部导航保持位置。画面有可见颗粒和轻微边缘色散。

本站学习空间与内容的层级、材质差异和环境延续，不复制粉色建筑、水景或重颗粒。tim 已明确不喜欢噪点、黑色叠影和灰场；这些不能以“参考风格”为由重新加入。

## 2. 艺术方向：午后将尽的温暖档案室

保持原有胡桃木、暖灰墙、深色金属、米色纸张、布料与绿植。明亮处是窗、台灯的有效照明和电脑内容；房间暗部要有形体层次，不能一律抬灰或压黑。红色继续属于 Stack 红线和档案标签，避免所有物件都同时发光。

画面分三层：前景少量桌沿/椅子/植物用于尺度；中景当前物品最清楚；背景保留窗、台灯、挂杆等地标。前景不得覆盖当前交互面或在转场中掠成整屏黑块。

每个停留镜头应有一个明确主体。装修丰富度靠近景的可信细节与物件使用痕迹建立，不能平均堆满所有空隙。

## 3. 光影要求

| 层次 | 目标 | 应检查的问题 |
| --- | --- | --- |
| 窗光 | 左侧偏冷、较大的柔和照明，塑造桌面和墙面体积 | 阴影方向是否始终来自窗；窗框影是否锯齿、漂移或穿透物品 |
| 台灯 | 局部暖光落在桌面、纸张和附近物件，灯罩内明亮 | 灯罩是否变成发白塑料；光是否不合理照穿灯罩或家具 |
| 间接光 | 书架内部、桌下和抽屉能辨识深度，颜色来自周围材质 | 是否靠强环境光把所有暗部抬成灰；是否与烘焙光重复计算 |
| 接触阴影 | 纸、书、杯子、抽屉与桌面接触处有重量感 | 贴图/印刷面是否重复投影产生锯齿、暗斑和悬浮感 |
| 反射 | 深色五金能反映周围亮面，木材有柔和掠射反光 | 金属是否死黑或泛白；反射环境是否与真实窗灯方向冲突 |
| 曝光 | 保持窗外与纸面层次，画面暗而可读 | 切章是否突然调整曝光；是否用曝光跳变掩盖加载或换面 |

现有网页运行时采用 AgX、方向窗光、台灯 spot、少量填充、PMREM 环境与已烘焙间接光。先校准这些来源的职责，不为“更顶尖”盲目新增多个实时光源。

## 4. 材质与纹理要求

| 材质 | 希望看到的响应 | 不接受 |
| --- | --- | --- |
| 胡桃木桌面 | 大尺度木纹明确、沿实际板材方向，漆/油层反光柔和，边缘有厚度 | 整桌等距密条纹、侧面拉伸、近景只有彩色噪声 |
| 书页/信封 | 米色纤维轻微，纸边与翻开姿态有厚度，印刷内容清晰 | 粗颗粒像砂纸、文字与照片染成糊块、页边深度冲突 |
| 深色金属 | 大面暗，倒角和掠射角有受控高光；拉丝方向连续 | 为规避异常把金属反射删除；过强法线导致闪烁白点 |
| 墙面 | 低频抹灰变化与微小粗糙度，光照变化负责大部分体积 | 大片重复图案、贴图接缝、噪点颗粒覆盖正文 |
| 布料/地毯 | 中景识别织物与图案，近景才出现纤维，边缘自然 | moiré 波纹、过锐细线、远景持续闪烁 |
| 电脑 | 真实内框和干净发光内容，反射不妨碍 Index 操作 | 全白反光遮住标题、假截图替代交互、背后的旧图片透出 |
| 照片 | 使用原图和正确裁切；色彩由图像本身主导 | 临时替代图、为配房间而重染肤色、内容中途换资源 |

当前 GLB 只读清单：18.05 MiB、77 meshes、54 materials、48 images；含 clearcoat、emissive strength、anisotropy、sheen 与 WebP 纹理扩展。数量不是质量评分。多个 RoomBake 材质有真实法线、PBR 贴图和带标记的间接光槽，优先检查采样、UV、强度与导出一致性；不能看到历史 extras 的“web bake required”字样就判定这些材质没有烘焙。

按最大实际画面占比评估有效纹素密度。4K 贴图并不自动意味着近景清楚；UV 占比、图像裁切和最终渲染分辨率都要一起记录。只提高最常见近景对象的必要资源，避免把整间房的贴图统一膨胀。

## 5. 像素与后处理

已发现的实际检查点：当前基线 `new EffectComposer(gl)` 默认创建 HalfFloat 渲染目标，项目本地 Three 的 RenderTarget samples 默认 0。renderer 的 `antialias: true` 不足以证明中间合成目标有抗锯齿。开发须在最终合成路径上明确采样或后处理 AA 策略，并记录实际硬件支持与成本。

- 原生 DOM 文字保持清晰，不在整站文字上叠景深、波纹、色散或 grain。
- 景深用于远近层次，焦点在当前阅读/交互物品；镜头停下后不抽动焦点。焦点与视觉尺寸变化连续，不能依赖突然开启/关闭来掩盖穿模。
- Bloom 只服务灯光和少量高亮，木纹、照片与白字不能泛成一片。保留 finite pass 在会扩散异常值的处理之前。
- 高 DPR 桌面优先保住清晰度，动态降载先降低无关动画/离屏更新，不能让用户在每次滚动时看到分辨率跳变。
- 若使用动态质量，记录触发阈值、恢复滞回与变更时机；不能根据硬件名承诺毫无限制的效果，也不能仅凭模糊的 deviceMemory hint 将强机永久降为低档。
- 显示器从远到近、金属高光经过掠射角、纸边接近相机、照片从透视归正都需要专门检查。

现有像素检测的 alpha===0 只能覆盖透明缺失；alpha:false 的输出不能据此证明没有不透明黑块。源 HDR 非有限值检测必须继续，最终图像检查应结合实际房间区域与异常覆盖范围，区分合法的黑色原站背景和错误的全黑矩形。

## 6. 相机与运动语言

| 路线 | 构图关系 | 主要动作 |
| --- | --- | --- |
| 开场 | 屏幕中心偏右、笔记本左下、台灯旁侧，窗与书架交代纵深 | 从第一帧即稳定可看；用户操作前不自动绕房间 |
| 电脑 → About | 始终共享桌面边缘与灯光方向 | 先轻微转向书，书开启，再推进；文字可读前完成归正 |
| About → Life | 打开的书、书架立柱是共同地标 | 抬眼到信封，照片抽出；避免镜头穿过书架 |
| Life → Frame | 窗侧到右墙，桌面或灯作为方位中介 | 转向与横向侧移有主次，先停稳再启动原横向内容 |
| Frame → Stack | 同一张 Final Horizon 在挂画与屏幕中短暂可对应 | 退开建立二者关系，转向电脑，再靠近图片 |
| Stack → Work | 电脑底座和桌沿连接抽屉 | 向下看、抽屉打开、档案抬起；不堆叠第二段 Laser 入场 |
| Work → Contact | 抽屉、打开的书、灯重新同框 | 抬起并少量退开，留出原 Contact 信息区域 |

滚动一律可寻址，停住即停止前进，倒滚复原相同姿态。可以有很短的输入平滑，但禁止相机、投影面、文字分别使用不同的长延迟追赶同一滚动进度。

点击导航的初始运动时长可取 0.6–1.2 秒，微交互 160–240ms；均是调节起点。体验是否丝滑由速度与加速度连续、运动距离及用户控制共同决定，不能把所有时间拉长来制造“高级”。交接中不能一边长距离移相机，一边让大段文字快速滚动。

正常路线不淡出到黑/灰再进入下一段。若安全路径尚未建立，应修路径或留在原有可读内容中，不能用遮罩覆盖后继续声称连续空间已完成。

## 7. 原站效果的责任边界

Index 的身份排版、粒子与文字交互存在于电脑本页；About 内容完整；Life 原图组；Frame 原横向叙事和弯曲图像；Stack 红线；Work Glass 和项目详情全部保留。相机停稳后，当前原章节获得主要视觉表达权。

空间不在正文背后与前景粒子、Glass、弯曲照片同时争抢注意力。房间可持续存在而按需绘制；当前内容需要 GPU 时，其他看不见的效果应停止更新。
