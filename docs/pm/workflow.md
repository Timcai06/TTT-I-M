# PM 协作流程

版本：1.1，2026-09-09。

> 当前阶段仅规划，用户确认前不派发实现卡。[叙事内核迁移计划](narrative-runtime-plan.md) 为待确认的新技术路线；其中 About → Life → Frame 替代下表旧默认样段候选。角色、模型与初始化提示词以 [会话说明](sessions/README.md) 为准。

## 责任与模型

以下是依据本机可选模型描述制定的起始分配，不是价格或能力实测排名。实际额度按账户与任务反馈调整，不承诺固定节省比例。

| 工作 | 首选模型 / 思考强度 | 用法 |
| --- | --- | --- |
| PM、创意取舍、跨层根因与关键审查 | GPT-6 Astra / high，难题 xhigh | PM 当前模型不自动改动；强模型用于高不确定性判断 |
| 空间运行时、投影、导航、渲染交接 | GPT-5.6 Sol / high | 主开发；复杂跨层问题升级 Astra |
| 边界明确的组件与样式实现 | GPT-5.6 Terra / medium | 按已确认任务卡实现，小范围变更 |
| 只读盘点、证据索引、简单整理 | GPT-5.6 Luna / medium | 不作全局架构和美术裁决 |
| 风险变更的独立技术复核 | GPT-5.6 Sol / high，必要时 Astra | 仅关键任务启用；简单任务由 PM 复核 |

首张现状盘点因工作区复杂，使用 Terra / medium。不默认选择 GPT-5.5 或更旧模型；也不以换成便宜模型本身作为节省成果。模型和思考强度在每次派发显式设置；不可用时报告并使用已可用的同级方案，不悄悄降低关键任务能力。

升级触发：同一问题修复两次仍失败；无法解释证据；需要跨模块改变约定；路径/回报失真；或任务实际超过卡片范围。停止重复猜测，提交最小复现和已排除原因，由 PM 缩小任务或升级模型。小修不因次数规则而强制做两轮。

## 一次迭代

1. **建立事实**：读取工作区、相关实现和已有报告；记录已观察问题与未验证判断。旧资料只作线索。
2. **PM 排序**：P0 为不可用/回归，P1 为主线体验，P2 为质感改进。优先级与证据强弱分开；未观察的问题不伪装成缺陷。
3. **设计任务卡**：一个可感知结果、一名负责会话、明确读写范围、依赖、可验证验收项和回退方式。过大的任务先拆成一个能完整体验的样段。
4. **派发**：工具向现有合适会话发送卡片路径、版本、模型和必要上下文；不让会话重读全库。已被用户停止的旧工作不自动恢复。新建会话仅在用户明确要求新建时进行。
5. **执行**：允许在边界内自行选择实现。发现旧规格不合理，先向 PM 报告证据和替代方案，继续不依赖决策的工作。不得自行扩展目标、派任务或安排后续运行。
6. **结构化回报**：完成卡片检查，报告实际差异、证据、未完成项与下一步建议；不得只说“已完成”。
7. **PM 复核**：检查实际差异和关键证据；必要时安排独立复核。结果为接受技术交付、返工、阻塞或提交 tim 视觉验收。用户验收不替代开发尚欠的功能。
8. **收口**：看板记录结论与回报链接，释放文件所有权，派下一张卡。技术通过后仅在新变更或新疑点出现时重复检查。

## 本阶段顺序

| 阶段 | 产出 | 进入下一步的条件 |
| --- | --- | --- |
| S0 现状盘点 | 当前版本、实现地图、证据有效性与问题候选 | PM 核实基线与写入范围 |
| S1 体验诊断 | 根据真实当前体验形成按优先级排列的问题及首个样段方案 | PM 明确可感知目标；涉及审美偏好时请 tim 判断 |
| S2 标杆样段 | 当前待确认候选为 About → Life → Frame；原入口保留回归 | 功能检查通过；tim 判断画面与节奏 |
| S3 全章精修 | 把已成立的交接原则扩展至其余章节，保留各章个性 | 逐卡复核，主线可双向完整浏览 |
| S4 质量收口 | 必要回归、实机可用性、性能与剩余问题清单 | PM 技术结论、tim 最终体验结论分别明确 |
| S5 发布准备 | 可审阅的差异、实际验证与已知限制 | 提交/推送/部署按当时用户授权执行 |

阶段不代表已排定开发工期；S0/S1 完成后才将具体实现卡标成 READY，不提前批量承诺无法核实的修复。

## 共享工作区与回退

- 当前多个会话共享实际 checkout。默认同时只开一个产品代码写入任务；只读审查可并行，PM 文档不与开发报告共用所有权。
- 看板是所有权登记，不是操作系统锁。PM 派发前检查其他会话状态；执行者开始前检查目标文件状态。发现其他人正在写同一文件，暂停该文件工作并报告。
- 独立模块并行须由 PM 先分配互不相交的文件；公共运行时、路由、全局样式、模型源/GLB/契约各自只允许一个任务写入。
- 记录 HEAD、起始差异、任务涉及文件哈希和未跟踪文件。当前脏工作区不可用 `git diff` 全量归功于单个任务，也不可用 HEAD 单独回退。
- 变更前保存任务范围的原始版本或可恢复补丁到独立任务证据目录；回退只还原本任务增量。多人改动重叠时由 PM 协调手工合并，禁止 reset/clean 或覆盖别人的未提交成果。
- Blender 与导出任务串行；卡片列明源文件、网页资产、契约与校验关系。证据留在唯一任务目录，不覆盖之前报告。
- 不为管理方便自动新建 worktree；若以后采用隔离工作区，先明确如何保留当前未提交资产与改动。

## 验收和额度

- 检查按风险选择：普通文档检查链接与一致性；简单样式变更不写镜像测试；空间/导航/加载变更检查相关行为及适当构建/类型检查。
- 本阶段不添加自动样式评分或截图差分门禁。功能性浏览器操作与实际观看属于不同证据；截图/录像若任务需要，用于说明和 tim 审阅，不充当自动美术验收。
- 报告分清：实现完成、技术验证、PM 复核、tim 体验验收。不可互相替代。`UNKNOWN`、`NOT_RUN`、`BLOCKED` 是有效结果。
- 不常驻一组空闲代理，不让每张卡经过多模型重复全面审计。默认一位执行者，PM 对关键问题定点复核。
- 单张卡通常覆盖一个完整可检查的结果；只读盘点保持简短。耗时偏离明显时先汇报原因，PM 决定继续、拆分或升级，不静默消耗额度。
- 记录实际耗时、返工轮次、模型；工具没有提供任务级 token/成本时写 unknown。账户剩余额度不能冒充单任务成本。
- PM 使用任务等待工具获取变化，不高频轮询；这一流程不创建自动化或后台持续监控。离线持续跟进另按用户要求安排。
