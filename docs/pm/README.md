## 文档使用原则

- 用户的最新明确指示优先。适用的系统、工具和 AGENTS 指令仍须遵守。
- 产品意图由产品简报维护；授权执行范围由当前已派发任务卡确定。发现冲突向 PM 报告，不自行推断旧会话仍授权继续工作。
- 源代码说明当前实现；运行证据说明实际检查结果；二者都不自动证明符合产品意图。
- `experience/` 中旧方案是可审查的设计资料；`delivery/` 是当时交付记录；`plan/` 是 Builder Graph OS 独立路线。本阶段不自动执行它们的任务或继承其“已完成”结论。
- 不因文档来自旧模型而否定，也不因标题写着“必须”而永久冻结实现。保留用户意图和真实证据，允许用更好的方案替换实现假设。
- 低成本执行模型可以报告事实、问题和替代建议；全局产品约束与任务优先级由 PM 维护。影响用户已确认方向的变更须让 tim 判断。
